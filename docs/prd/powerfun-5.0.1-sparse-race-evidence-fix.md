## 1．问题证据

### 1.1 分圈图与模型点评使用了两套不同的样本门槛

今天之前，精确同为 `half_marathon` 的历史活动只有 3 次：

- 2026-04-19 `585800938`；
- 2026-03-15 `573716122`；
- 2025-11-16 `539517502`。

`src/chart_generator.py` 的两张分圈图当前按每公里有效样本判断：

- 中位线：有效样本 `≥5`；
- P20–P80：有效样本 `≥10`。

因此今天 21 公里的历史中位配速、心率均为 `null`，本次曲线正常。图表本身符合既定门槛。

但 `DeepRunAnalyzer._analyze_laps()` 对 Prompt 的另一套计算没有相同门槛：只要有 1 个样本就计算中位数和 P20–P80。今天 `.runtime/llm/662381792/request.md` 因而包含基于 3 次活动的历史中位配速和区间，response 进一步写出“多数圈次快于历史中位配速 20 秒以上”。

这是确定性内核内部的不一致，不是模型单纯自由发挥。

### 1.2 整体对比提前返回，导致两张报告区块消失

`_compare_with_history()` 当前只尝试：

1. 近 90 天同温区；
2. 近 90 天跨温区；
3. 近 180 天跨温区。

今天近 180 天赛事归并池只有 2 次，不足最低 3 次；没有跨全年描述性兜底，于是提前返回：

```text
sample_size = 0
message = 最近无同类型跑步记录，无法对比
```

提前返回使短期、长期、百分位和预期配速等后续模块没有进入 `comparison`。`analysis_report.py` 又只在相应结果存在时渲染，因此：

- “对比分析（同类型中位数）”整张消失；
- “状态与趋势”整张消失。

独立调用短期、长期计算，二者实际都返回“样本不足”。正确行为应是展示明确的空状态，而不是隐藏区块。

### 1.3 空状态没有进入 Prompt，文字产生无依据趋势

今天 request 的“历史对比”只有指标口径说明，没有明确说明短期、长期均不可判断。response 写出：

> 以本场完赛成绩结合近月训练斜率判断，能力曲线仍在上升通道。

当时没有长期月度斜率提供给模型，该结论没有数据支撑。

### 1.4 残圈口径也不一致

- 图表历史基线保留 `distance_m >= 950` 的圈；
- `_analyze_laps()` 使用 `distance_m >= 1000`。

本批统一历史分圈统计时必须一并消除该差异，否则即使样本阈值一致，输入样本仍可能不同。

## 2．修复目标

1. 图表、结构化 `analysis_data` 和 Prompt 共用同一份每公里历史统计及有效样本证据。
2. 稀疏课型不再因整体对比为空而丢失短期、长期等独立模块。
3. 整体中位数对比增加跨全年描述性兜底，但不把小样本包装成能力方向证据。
4. 报告明确展示“样本不足／仅作描述”，不再无声隐藏两张区块。
5. Prompt 在无中位数、无斜率时明确禁止对应比较和能力趋势推断。
6. 普通课型的既有数值、图表和报告行为不回归。

## 3．明确不做

- 不把每公里中位线门槛从 5 降到 3，不把 P20–P80 门槛从 10 降低。
- 不把 10K、全马混入半马的每公里分圈基线；分圈继续使用精确 `category`。
- 不改变整体对比既有赛事归一化：`full_marathon/half_marathon/race_event → race`。
- 不扩大短期 60 天、长期及同比 180 天窗口，不改变其证据门槛。
- 不改变同温区优先、跨温区回退及 LSD `no_temp` 规则。
- 不修改人工课型、Pa:Hr 选段、负荷、强度、技术效率或间歇分析。
- 不重构 Garmin 数据管道，不回写 parquet，不补拉历史数据。
- 不修改六小节及 `<<<BRIEF>>>...<<<END>>>` 协议。
- 不调用外部模型 API，不生成正式报告或写正式缓存，不 commit／push。

## 4．F1：统一每公里历史统计入口

### 4.1 单一事实来源

以 `DeepRunAnalyzer._analyze_laps()` 为每公里历史统计的唯一入口，输出供结构化分析、Prompt 和两张图表共同消费。

`chart_generator.py` 不得再各自遍历 `recent_laps`、重新计算历史中位数或 P20–P80。`main.py` 已先构造 `lap_data`，应将同一份结果传给图表；如保留旧函数签名作包装，也只能读取统一统计结果。

P20–P80 的居中平滑可以保留为纯图表展示变换，但不得回写结构化统计；Prompt 使用未平滑的统一统计值。

### 4.2 统一过滤及证据规则

历史基线过滤及 IQR 规则以当前图表实现为准，避免借一致性修复调整数值口径：

- 残圈：`distance_m < 950` 剔除；缺距离字段保守保留；
- 中位数：当前公里、当前指标有效样本 `≥5` 才提供；
- P20–P80：当前公里、当前指标有效样本 `≥10` 才提供；
- IQR：沿用当前图表的启用规则；
- 配速和心率分别计算有效样本数，某一指标不足不得拖累另一指标；
- 不足值统一用 `None`，不得以 0 冒充有效数据。

本次曲线和横轴距离取整保持当前图表行为，不借本批修改本次分圈展示。

### 4.3 结构化结果

在 `lap_data` 中保留现有字段并补齐统一证据字段。字段名可微调，但必须完整表达：

```text
sample_size                         历史活动数
baseline_note                       基线构成
history_median[lap].pace_sec        每公里历史中位配速或 None
history_median[lap].avg_hr          每公里历史中位心率或 None
history_p20_pace / history_p80_pace 每公里配速区间或 None
history_p20_hr / history_p80_hr     每公里心率区间或 None
per_km_samples[lap].pace            配速有效样本数
per_km_samples[lap].hr              心率有效样本数
```

必须能区分“活动池有 3 次”和“某一公里某指标有 3 个有效值”。不得只用总活动数推断每公里证据充足。

### 4.4 报告说明

保留“对比前 N 次同类型跑步”的基线标注，并在历史中位线不可用时给出明确原因。例如今天应表达：

```text
历史中位线需每公里至少 5 个有效样本；本次各公里样本不足，仅展示本次曲线。
```

若只有部分公里可显示，则不得笼统声称全部公里都有／都没有中位线。

## 5．F2：整体对比增加跨全年描述性兜底

### 5.1 基线选择链

整体 `_compare_with_history()` 在现有三档之后增加：

```text
跨全年、同类型归并池、不限温区，活动数 ≥3
```

仅当前三档都无法形成基线时使用。返回结果必须明确标识：

```text
baseline_scope = all_temp
baseline_window = all_history
evidence_level = descriptive
verdict_allowed = false
```

字段名可调整，但 HTML 和 Prompt 必须能识别“跨全年描述性兜底”，不能将其误标为近 90／180 天证据。

### 5.2 展示与判断分离

跨全年兜底可以保留：

- 心率、配速、功率、垂直振幅比、效率等描述性中位数和差值；
- 距离相近子集信息；
- 基线活动数。

但不得输出“更快、更累、更经济、进步、退步”等方向 verdict。相应徽标统一为“样本有限／仅作描述”，并注明课程、天气、比赛目标可能不同。

保留现有距离相近子集逻辑，但新增返回实际子集活动数。跨全年兜底时，HTML／Prompt 不得把基线池总数笼统写成所有指标共同的“有效样本数”；应明确：

- 基线池共 N 次；
- 其中心率／配速／功率／效率使用距离相近子集 M 次（若触发该子集）。

本批不重构普通窗口内 ability／economy 的既有样本池行为。

### 5.3 今天场景的预期

今天既有赛事归并池跨全年共 7 次；按既有距离 ±20% 规则，心率／配速／功率／效率的距离相近子集应为 4 次。报告应显示跨全年描述性整体对比，并明确上述两个数量及“仅作描述”。

这 4 次是整体活动指标对比，不得拿去填补半马每公里分圈中位线；分圈仍只有 3 次精确半马历史活动。

## 6．F3：取消提前返回造成的模块丢失，补齐空状态

### 6.1 独立计算

即使整体同类型中位数基线为空，`_compare_with_history()` 也必须继续独立计算并返回：

- `short_term`；
- `long_term`；
- `tech_changes`；
- `percentile`；
- `expected_pace`。

整体对比为空时保留 `sample_size=0`、明确 `message` 和空 `ability/economy`，但不得提前丢弃上述模块。

### 6.2 两个报告区块始终有确定状态

`analysis_report.py` 应按结构化结果显示内容或空状态：

- 有整体对比：显示中位数表格及证据标签；
- 无整体对比：保留“对比分析（同类型中位数）”区块，说明无法形成基线的原因；
- 短期不足：显示“短期样本不足”及实际样本数，不显示 `None`；
- 长期不足：显示“长期样本不足／数据不足”，不得因为没有斜率而隐藏整个“状态与趋势”；
- 百分位、预期配速等无数据时可以省略对应行，不得显示伪造的 0。

今天应至少看到“对比分析”的跨全年描述性内容，以及“状态与趋势”的短期、长期不足说明。

## 7．F4：Prompt 空状态与缓存失效

### 7.1 分圈 Prompt

`_format_lap_data()` 只消费统一后的 `lap_data`：

- 中位样本不足时不得输出小样本中位数；
- 区间样本不足时不得输出 P20–P80；
- 不得仅用 `--` 让模型自行猜测原因，应给出明确样本不足说明；
- 可以要求分析本次配速均匀性、心率变化和前后程表现；
- 没有历史中位数的公里，不得要求或引导模型比较“快于／慢于历史中位数”。

### 7.2 整体及趋势 Prompt

`_format_comparison()` 必须消费 `comp.message`、短期和长期空状态，明确输出：

- 无整体基线时：无法形成同类型中位数对比，禁止方向判断；
- 跨全年兜底时：只作描述，禁止能力进步／退步判断；
- 短期不足时：不得判断近期状态方向；
- 长期不足且未提供斜率时：不得写“能力上升／下降／上升通道／近月训练斜率”等结论。

六小节结构保持不变。短期、长期不足时各用一句话说明即可，不得用本场成绩替代不存在的回归证据。

### 7.3 缓存版本

本批改变 Prompt 的证据输入和约束文本，必须：

```text
LLM_PROMPT_VERSION：12 → 13
```

原因是仅修改 `_format_comparison()` 或 `_format_lap_data()` 不一定改变 `analysis_hash`；不提升 Prompt 版本会继续命中旧 response。六小节和 BRIEF 协议不变，但这次 Prompt 内容变化必须可靠失效旧缓存。

旧版本缓存只安全未命中，不删除、不改写。新增结构化分圈字段引起的 `analysis_hash` 自然变化继续保留。

## 8．测试要求

不得只验证 HTML 标题存在，必须核对结构化数值、Prompt 和图表一致。

### 8.1 合成分圈边界

1. 每公里 3 个有效样本：配速和心率中位数、P20–P80 均为 `None`，图表与 Prompt 一致。
2. 每公里 5 个有效样本：有中位数，无 P20–P80。
3. 每公里 9 个有效样本：仍无 P20–P80；10 个时才出现。
4. 配速足够、心率不足及反向场景：两指标独立降级。
5. `950–999m` 历史圈：两条链路采用相同样本，不再一个保留、一个剔除。
6. 部分公里足够、部分不足：不得全图一刀切。

### 8.2 整体对比与空状态

1. 近 180 天不足 3 次、跨全年至少 3 次：进入 `all_history` 描述性兜底，无方向 verdict。
2. 跨全年也不足 3 次：整体对比为空，但短期、长期等键仍独立返回。
3. 短期／长期不足：HTML 两个区块均有明确空状态，无 `None`、NaN 或伪造 0。
4. 跨全年距离相近子集：基线池 N 与子集 M 分别返回并正确展示。
5. Prompt 无斜率时包含明确禁止趋势推断的证据说明。

### 8.3 今天真实场景 `662381792`

使用只读 parquet 与分圈缓存回放，至少断言：

- 分圈历史池为 3 次精确半马，标注“跨全年 3 次”；
- 各公里配速／心率中位线均不显示，P20–P80 不显示；
- Prompt 分圈段不再出现基于这 3 次活动的历史中位配速或区间，并明确禁止历史快慢比较；
- 整体对比进入跨全年描述性兜底，基线池 7 次、距离相近子集 4 次；
- 短期、长期均明确样本不足；
- HTML 同时保留“对比分析”和“状态与趋势”两个区块；
- Prompt 不含可供“近月训练斜率／上升通道”引用的虚构数据。

### 8.4 普通课型回归

至少复跑：

- 2026-11-12 `661585068`：短期 13、长期 56、6 个有效月份、P73、Pa:Hr `+0.92%`，既有分圈图中位数／区间不回归；
- 三个人工活动：课型、Pa:Hr、问题清单不变；
- 2026-11-06 新节奏课型：整体基线仍可为 0，但报告与 Prompt 必须给明确空状态，不再静默缺区块。

全量既有测试必须通过。确实因空状态展示而需要更新断言时，必须记录旧值→新值→本 PRD 条款，不得删除历史场景。

## 9．隔离验证与数据安全

- 所有回放只读正式 parquet 和分圈缓存；图表、HTML、Prompt、response 及缓存测试写入 `.runtime/acceptance/sparse-race/` 或测试临时目录。
- 不生成或覆盖正式 `reports/`，不写正式 `cache/`，不修改正式 `data/`。
- 执行前后分别生成正式 `data/`、`reports/`、`cache/` 的路径、大小、mtime、SHA-256 清单并比较一致。
- 如需由执行会话生成今天的隔离 response 验证文字，只能使用当前会话模型并走既有两阶段协议，不得调用外部 API；隔离 response 不得写正式缓存。
- 今天正式报告在本批验收前保持原样，验收后再由老板决定是否重新生成。
