# PowerFun 5.0.2 PRD：比赛参照、技术解释与教练点评语义修复

- 日期：2026-11-15
- 状态：**已实施并通过主会话验收（2026-11-15）**
- 当前产品版本：5.0.1
- 目标补丁版本：5.0.2（全部验收通过后修改）
- 当前 Prompt 版本：`LLM_PROMPT_VERSION = 13`
- 目标 Prompt 版本：`LLM_PROMPT_VERSION = 14`
- 触发场景：2026-11-15 横店半程马拉松，activity_id `662381792`
- 执行方式：执行会话只实施本批；主会话独立验收合格后才发布
- 前置复核：[比赛分析复核与老板补充决策](../audits/2026-11-15-powerfun-race-analysis-review.md)

## 1．背景与根因

### 1.1 5.0.1 修复了局部证据问题，但重写了整篇点评

5.0.1 将 Prompt 从 12 升到 13，删除小样本分圈历史比较、将跨全年赛事对比统一降为描述，并增加短期／长期禁令。旧 response 因版本升级不再命中，全文重新生成。

这消除了旧文本两条无依据结论，但新生成文本丢失了原有点评中较正常的比赛分析，退化为围绕禁令和问题清单填空。上次方案沟通没有把“整篇点评会重新生成”说明为产品风险，验收也缺少新旧文本语义对照。

### 1.2 比赛参照物被过度限制

老板确认的比赛原则：

> **半马与全部历史半马比较，全马与全部历史全马比较；赛道、气温、海拔、人数、比赛目标等用于解释差异，不用于排除样本。**

比赛成绩和执行比较是有价值的，不能因为条件不同就全部降为“仅作描述”。成绩进步可以明确描述；是否代表纯能力进步，再依据赛道、天气、目标和训练证据判断。

### 1.3 技术变化被机械命名为改善

本场技术规则实际执行为：

1. 相近功率 ±8 W：0 次；
2. 相近配速 ±15 秒：2 次，不足 3 次；
3. 放宽为全马／半马混合 5 次，功率 211–277 W，本场 287 W；
4. Prompt 仍称“相近功率基线”，并把步幅、VR、GCT 的方向性变化全部标为“改善”。

步频基本持平、配速明显提高时，步幅增加首先是机械结果。比赛和节奏跑的强度变化必须进入解释，不能自动等同技术进步。

### 1.4 比赛问题探测器混淆不同性质

- 比赛 Pa:Hr 被自动列为执行问题；负分段比赛中前后强度不同，本身就会形成前后效率差异。
- 比赛负荷与赛前减量期近 4 次混合课型均值比较，被自动列为“负荷激增”。
- 最大心率超过配置被自动列为执行问题，而实际应是设备／配置待核验。
- 赛前计划、检查点和天气调整没有进入 Prompt，却允许模型自行判断计划偏离。
- 分圈爬升已经存在于本地数据，但未进入分析。

## 2．已确认的设计原则

1. **同距离是比赛参照池边界**：`half_marathon` 只比较历史半马，`full_marathon` 只比较历史全马，不再混池。
2. **其他条件不作硬筛选**：不因功率、配速、温度、赛道、海拔、爬升、人群或目标不同排除同距离历史比赛。
3. **成绩比较与能力结论分层**：允许“成绩更快／更慢、某段执行更稳／更差”；不得仅凭少量比赛直接写“纯能力上升／下降”。
4. **技术变化与技术改善分层**：同距离全部比赛可用于技术参照，但步频、步幅、GCT、VR 只先称变化，并结合强度解释，不自动称改善。
5. **异常驱动技术小节**：没有需要修正的技术异常时不逐项分析；无可信异常不硬凑练习建议。
6. **普通训练不改**：轻松跑、有氧跑、LSD、人工节奏／间歇的既有基线、统计门槛和 Pa:Hr 规则保持不变。
7. **不再只验收结构**：除数值与六小节外，必须验收教练语义、比赛语境和新旧文本质量。

## 3．目标

1. 同距离全部历史比赛形成成绩参照池，恢复有实际价值的成绩和执行比较。
2. 小样本同距离比赛可提供参考中位轨迹，但明确样本数，不包装成稳定统计区间或能力趋势。
3. 比赛技术指标不再自动输出“改善”，技术小节改为异常驱动。
4. 比赛 Pa:Hr、负荷和最大心率不再自动进入执行问题清单。
5. 重点比赛可输入结构化计划，按计划赛段、检查点、天气调整和爬升复盘。
6. 横店半马生成一份真正结合目标、赛道、执行和自述的教练点评。
7. 普通课型及人工节奏／间歇无回归。

## 4．明确不做

- 不修改 Garmin 数据、parquet、分类器和人工课型覆盖。
- 不修改普通课型的短期／长期统计门槛、温度策略、百分位门槛。
- 不修改普通课型 Pa:Hr 计算、人工节奏／间歇选段及间歇不适用规则。
- 不把全马混入半马，也不把半马混入全马；10K 等其他赛事不与半马／全马混池。
- 不因样本少而伪造 P20–P80 区间或能力趋势。
- 不让程序自由解析训练 Markdown，不让模型凭记忆补比赛计划。
- 不把赛后恢复和下一训练阶段目标伪装成“比赛执行问题”。
- 不修改六小节和 `<<<BRIEF>>>...<<<END>>>` 协议。
- 本批执行阶段不刷新正式深析、不写正式 LLM 缓存、不更新综合报告，不 commit／push。

## 5．F1：同距离比赛成绩参照池

### 5.1 适用范围

仅当活动 `category` 为：

- `half_marathon`；
- `full_marathon`。

其他 `race_event` 暂不并入半马／全马池，沿用现有行为；不得通过距离相近规则把 10K、其他赛事或全马塞进半马成绩池。

### 5.2 参照池

对目标比赛使用：

```text
同一精确 category + 目标日期之前的全部历史活动 + 排除当前 activity_id
```

不再对上述比赛池执行以下排除：

- 90／180 天窗口；
- 温区；
- 平均功率或配速相近；
- 距离 ±20% 子集；
- 赛道、爬升、海拔或比赛目标相近。

保留各活动上下文字段供解释：日期、标题、完赛时间、距离、配速、心率、功率、效率、温度、爬升；缺失字段明确未知，不补 0。

### 5.3 结果字段与语义

为比赛整体对比增加明确证据类型，例如：

```text
comparison_kind = same_distance_race_history
baseline_window = all_history
result_comparison_allowed = true
ability_verdict_allowed = false
sample_size = 实际同距离历史场次数
```

字段名可调整，但 HTML、Prompt 和结构化结果必须能区分：

- **成绩／执行比较**：允许；
- **纯能力方向结论**：不能仅由该池推出。

允许输出：

- 当前完赛成绩／配速与同距离历史中位数的差值；
- 当前心率、功率、效率与同距离历史中位数的差值；
- 当前前后程执行与历史比赛的差异；
- “本场成绩较历史半马中位更快”等结果级描述。

禁止输出：

- 仅凭该池写“能力曲线上升／下降”；
- 把不同比赛条件忽略后，将成绩差全部归因于体能；
- 用本场成绩替代不存在的短期／长期回归证据。

### 5.4 小样本处理

- 1 场历史比赛：保留逐场比较，不计算或强调统计中位数；
- ≥2 场：可展示中位数和范围，并始终标注实际场次数；
- 少量样本不妨碍成绩差值描述，但不得包装成稳定能力排名；
- P20–P80 区间继续执行现有样本门槛，不因为允许成绩比较而提前展示。

### 5.5 报告展示

“对比分析”中，比赛应显示“同距离历史比赛／成绩参照”及实际场次数，不再笼统显示“仅作描述”。

“状态与趋势”仍独立显示短期、长期真实证据状态；不得把成绩参照池伪装成短期或长期能力基线。

## 6．F2：比赛分圈参考中位轨迹

### 6.1 比赛专用门槛

半马／全马分圈历史池继续使用精确 `category`，与 F1 同距离原则一致。

新增比赛专用中位线规则：

```text
RACE_LAP_MEDIAN_MIN_SAMPLES = 3
```

- 每公里有效同距离比赛样本 ≥3：允许显示历史中位配速／心率，标签注明实际场次数，例如“3 场半马参考中位”；
- <3：不显示中位线，保留本次曲线及原因；
- P20–P80 继续使用现有 `LAP_BAND_MIN_SAMPLES = 10`，本批不降低；
- 残圈和有效值规则继续由统一统计模块处理，不新增第二套实现。

普通课型的中位线 `n≥5`、区间带 `n≥10` 不变。

### 6.2 允许的点评

允许：

- “第 X km 快于／慢于 3 场半马参考中位”；
- “本场某赛段较历史同距离比赛更稳／波动更大”；
- 将分圈差异与比赛目标、赛道、气温、爬升、人群和配速策略结合解释。

禁止：

- 用“多数圈快于历史中位”直接推出能力上升；
- 将 3 场参考中位写成稳定统计真值；
- 在没有 P20–P80 数据时自行描述历史区间。

## 7．F3：技术效率改为变化解释与异常驱动

### 7.1 比赛技术参照

半马／全马技术参照使用 F1 的同距离全部历史比赛，不再执行：

- 全马／半马混合；
- 功率 ±8 W 或配速 ±15 秒硬筛选；
- 异质全量放宽后仍宣称“相近功率基线”。

比赛技术中位数至少需要 3 场同距离历史比赛；不足时只保留逐场背景，不给技术稳定／改善／异常结论。

### 7.2 变化不再自动等于改善

对比赛：

- 步幅、步频只作为配速／功率变化的机械背景，不进入“技术改善”清单；
- VR、GCT 可返回 `change` 和差值，但 `direction` 不得自动写 `improved`；
- Prompt 数据段不得再使用【改善项】诱导点评；如确需展示，使用【变化项】并附强度背景；
- 不得仅因步幅增加、GCT 缩短或 VR 降低就给出技术训练建议。

普通训练的长跨度技术比较规则暂不重构，但必须修复状态表达：

- 有合格基线且无显著变化，才可写“长期稳定”；
- 无合格基线，必须写“缺少可比基线，不作技术评价”；
- 两者不得继续共用一个无状态空列表。

### 7.3 技术小节异常驱动

技术小节只处理可信的、需要修正的技术异常：

- 没有异常：一句固定收尾，不逐项罗列变化，不给练习建议；
- 基线不足：一句“本次缺少可比技术基线，不作技术评价”，不得写“稳定”；
- 有异常：说明证据、对本次执行的影响和对应修正，禁止泛泛夸赞。

技术异常探测器必须与参照池使用同一口径。比赛不足 3 场时不得触发技术异常；不得为了触发异常而再次放宽到异质池。

本批不修改报告顶部既有技术绝对分级徽章，避免把点评语义修复扩大为指标体系重做。

## 8．F4：比赛问题、恢复与数据提示分类

### 8.1 比赛执行问题清单

对 `half_marathon`／`full_marathon`：

1. Pa:Hr 数值保留在分析数据中，但**不自动生成执行问题**；Prompt 禁止将其与同源分圈心率／配速称为“相互印证”。
2. 不应用“近 4 次不限课型负荷均值 ×1.5”判定比赛负荷激增；负荷只用于强度和赛后恢复背景。
3. 最大心率超配置不进入执行问题，转入 `data_notes`／配置提示。
4. 技术异常只有满足 F3 门槛才进入问题清单。
5. 计划偏差只能来自 F5 的结构化计划及确定性赛段对比；无计划配置时禁止判断计划偏离。

### 8.2 数据／配置提示

最大心率超配置时，提示：

- 当前峰值与配置不一致，需要结合连续高强度记录和设备可靠性核验；
- 在核验前，谨慎解释依赖当前 max_hr 的心率区间占比；
- 不直接给出“提高比赛配速”“增加强度课”等无关修正。

### 8.3 恢复与下一训练目标

- 比赛负荷和主观“接近极限”可用于恢复建议，但恢复事项不得写成比赛做错的问题。
- 跑者提出的间歇／节奏目标属于下一阶段安排，不得由单次 Pa:Hr 直接推导课表。
- 没有真实执行问题时，“问题与修正”不得凑数；可只写一句本次无需针对执行做额外修正。

非比赛课型的问题探测器保持现状。

## 9．F5：可选结构化比赛计划

### 9.1 配置方式

新增可选 `config/race_plans.toml` 及轻量读取模块，按比赛日期关联。不得修改 `activity_overrides.toml` 的人工课型语义。

建议结构：

```toml
schema_version = 1

[races."2026-11-15"]
name = "横店半程马拉松"
category = "half_marathon"
target = "1:48"
strategy = "前7km克制，15km检查后再决定是否渐进提速"
weather_rule = "气温>18°C或湿度>75%时整体降3-5秒/km，目标放宽至1:49-1:50"
heat_threshold_c = 18.0
heat_pace_penalty_min_sec = 3
heat_pace_penalty_max_sec = 5
heat_adjusted_target = "1:49-1:50"

[[races."2026-11-15".segments]]
start_km = 1
end_km = 2
pace_min_sec = 310
pace_max_sec = 312
note = "能完整说话，不看人群不抢速"

[[races."2026-11-15".checkpoints]]
distance_km = 5
anchor_sec = 1535
upper_sec = 1570
action = "只慢不快，不追"
```

其余赛段和检查点按 `docs/training/2026-heng-dian-half-marathon.md` 第七节完整录入，不能只录第 9／12 km。

### 9.2 校验

- 日期、类别、赛段、检查点必须合法；
- 赛段按公里递增，配速上下限合法；
- 天气调整阈值、降速秒数和调整后目标必须为合法数值／文本，不得只依赖自由文本让模型自行计算；
- 配置无法解析时清晰报错，不静默忽略；
- 无配置时正常生成报告，但禁止计划偏离判断；
- 配置内容必须进入 `analysis_hash`，修改计划后旧 response 不得误命中。

### 9.3 赛段确定性统计

有计划时按计划赛段计算并注入 Prompt：

- 配速：赛段总时长／总距离；
- 心率、功率：按分圈时长加权；
- 爬升：赛段分圈求和；
- 原始计划配速区间与实际差值；
- 天气规则触发时，由内核按活动中值温度和结构化秒数计算调整后配速区间、调整后目标；湿度缺失时明确未参与判断，不得由模型自行估算；
- 同时提供原始计划与天气调整后计划，避免把实际执行只与其中一种口径比较；
- 检查点实际累计时间、锚点和窗口上限；如计划规定天气调整检查点，也由内核计算后提供；
- 跑者自述原文。

无计划时只分析实际曲线，不自行创造目标赛段。

## 10．F6：Prompt 与教练语义

### 10.1 必须保留

- 六小节标题、顺序和 BRIEF 协议；
- 跑者自述原文；
- 数值只来自确定性内核；
- 普通课型既有证据约束。

### 10.2 比赛点评指令

- 优先回答：目标是否实现、成绩相对同距离历史如何、执行哪里好／哪里偏离、外部条件怎样影响、下一步真正需要改什么。
- 有计划时按计划赛段分析，不任意创造与计划无关的前／中／后段。
- 删除“必须指出热身不足／后程过猛／心率漂移”等诱导性措辞；只有证据存在时才使用这些标签。
- 不得把 Pa:Hr 与同源分圈数据称为独立互证。
- 不得把比赛末段高心率自动等同后程失控。
- 不得只摘取第 9／12 km，必须解释整个赛段及检查点。
- 技术指标无异常时不硬分析。
- 问题清单为空时不凑建议，恢复与下一训练目标不得伪装成问题。

### 10.3 缓存版本

本批改变结构化比较、技术语义、比赛计划和 Prompt，必须：

```text
LLM_PROMPT_VERSION：13 → 14
```
