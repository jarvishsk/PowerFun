## 二、本批必须完成的六项改造

### F1．同距离比赛成绩参照池

- 半马只与全部历史半马比较，全马只与全部历史全马比较；10K、其他赛事和另一距离不得混入。
- 不因时间窗口、温度、功率、配速、赛道、海拔、爬升、人群或目标不同排除同距离历史比赛。
- 允许成绩和执行方向比较，例如“本场成绩较历史半马中位更快”；不得仅凭少量比赛写纯能力上升／下降。
- 成绩参照与短期／长期能力趋势必须分开，不能用比赛成绩池替代不存在的回归证据。

### F2．比赛分圈参考中位轨迹

- 比赛继续使用精确 `category`。
- 半马／全马每公里有效样本 ≥3 时显示参考中位配速／心率，并标明实际场次数；<3 不显示。
- P20–P80 仍需 ≥10，不降低。
- 普通课型中位线 n≥5、区间带 n≥10 不变。
- 继续复用统一分圈统计，不得新增第二套残圈、IQR 或样本计算逻辑。

### F3．技术效率异常驱动

- 比赛技术参照使用同距离全部历史比赛，不再混合全马／半马，也不再因功率或配速不同排除。
- 步幅、步频只作强度相关背景；VR、GCT 只称“变化”，不得自动返回或展示为 `improved`。
- 比赛技术中位数不足 3 场时，不给稳定、改善或异常结论。
- 无异常只一句收尾；无基线写“不作技术评价”，不得写“长期稳定”。
- 普通训练既有长跨度技术规则不重构，但必须区分“有基线无变化”和“无合格基线”。

### F4．比赛问题、恢复与配置提示分类

- 半马／全马 Pa:Hr 保留数值，但不自动生成执行问题。
- 比赛不应用“近 4 次不限课型负荷均值 ×1.5”的负荷激增规则。
- 最大心率超配置转入数据／配置提示，不作为比赛执行问题；提示心率区间占比也依赖该配置。
- 没有结构化计划时禁止判断计划偏离。
- 恢复和下一训练目标不得伪装成问题；非比赛问题探测器保持不变。

### F5．结构化比赛计划与赛段证据

- 新增可选 `config/race_plans.toml` 和轻量读取模块，不改变 `activity_overrides.toml` 的人工课型语义。
- 按 PRD 完整录入横店六段计划、全部检查点和结构化天气调整，不得只录第 9／12 km。
- 配置必须校验并进入 `analysis_hash`；无配置不阻断报告，但禁止计划偏离判断。
- 赛段配速＝总时长／总距离；心率和功率按分圈时长加权；爬升求和。
- 天气触发、调整后配速区间和目标由 Python 计算；不得让模型自行换算。
- 横店赛段与检查点必须复现 PRD 9.4 的数值。

### F6．Prompt 与缓存

- `LLM_PROMPT_VERSION`：13→14；`VERSION` 本批执行期间保持 5.0.1。
- 六小节和 BRIEF 协议不变，跑者自述原文保留。
- 删除诱导模型硬找“热身不足／后程过猛／心率漂移”的措辞。
- 不得把 Pa:Hr 与同源分圈数据称为相互印证，不得把末段高心率自动等同失控。
- 技术无异常不硬分析，问题为空不凑建议。
