- **日期**：2026-08-27
- **项目**：`~/Projects/skills/PowerFun`
- **前置**：PRD-insights-rework.md（v1 已上线，commit f13c1bf）
- **老板决策**：现有「异常触发制」导致卡片太少（只有 1 张），改为固定维度体检式；明确**不要**跑步技术、比赛与恢复两个维度

## 目标

「🎯 训练结论与下一步」改为**固定 4 张维度卡**，每张卡无论好坏都输出结论（维度体检式，非异常触发），状态着色复用现有 type（info=正常✅ / tip=建议 / warning=警告）。

**固定 4 卡，顺序固定**：

### 卡 1：🏗️ 强度结构

- 数据：近窗口（沿用 v1 的 4 周窗口 + 8/12 周降级）hr_zone 分布
- 判定：
  - Z1 占比 < 30% → warning「有氧基础不足」：文案含 Z1 上限心率（同 v1 算法：resting + 0.74×HRR）、建议轻松跑次数
  - 30% ≤ Z1 占比 ≤ 50% → info「强度结构合理」
  - Z1 占比 > 50% → 统计窗口内 Z3/Z4/Z5 次数：
    - 强度次数 = 0-1 次 → tip「强度刺激不足」：如"近 4 周 Z1 占比 91.7%，仅 1 次强度刺激。若有比赛目标，建议每周安排 1 次节奏跑或间歇"
    - 强度次数 ≥ 2 次 → info「轻松跑为主，强度点缀合理」
  - Z5 占比 > 20%（独立判断，可与上面并存时合并为一张卡，优先级高的状态为准）→ warning「高强度过多」
- 注：Z1 占比与 Z5 占比合并为这一张卡，不要拆成两张

### 卡 2：📦 训练负荷

- 数据：近窗口总跑量 vs 前一等长窗口（沿用 v1 逻辑），周均跑量
- 判定：
  - 环比 > +20% → warning「跑量增长过快」，给出下周建议区间（前周期 1.1-1.2 倍）
  - 环比 < -20% → tip「跑量下降」，给出恢复建议区间
  - 否则 → info「负荷稳定」：如"近 4 周跑量 184 km（周均 46 km），环比 -1%，负荷稳定"
  - 前一窗口无数据（prev=0）→ 只展示当前跑量，info「负荷基线建立中」

### 卡 3：💓 有氧效率

- 数据：心率成本 beats/km = avg_hr × (avg_pace_sec / 60)，近窗口均值 vs 前窗口均值
- 判定（以前后窗口均 ≥3 次有效记录为前提，需 avg_hr>0 且 avg_pace_sec>0）：
  - 下降 ≥2% → info「有氧效率提升」：如"心率成本从 158 降至 153 beats/km（-3.2%），同等配速下心率更低，有氧效率在进步"
  - 上升 ≥2% → tip「有氧效率回落」：提示可能与气温、疲劳、状态有关，建议观察
  - 变化 < ±2% → info「有氧效率平稳」
  - 样本不足 → info「效率基线积累中」，不判定趋势
- 注意：效率值越高越差（每公里心跳次数多），文案方向别写反

### 卡 4：🔄 训练连续性

- 数据：近窗口次数 / 窗口周数 = 周均次数；距上次跑步天数
- 判定：
  - 距上次 > 7 天 → warning「训练空窗期」（沿用 v1 文案）
  - 周均 ≥ 3 次 → info「训练规律」：如"近 4 周 12 次（周均 3.0 次），训练规律"
  - 周均 2-3 次 → info「训练基本规律」
  - 周均 < 2 次 → tip「频率偏低」：建议提升到每周 3 次

### 删除

- v1 中的独立「步频偏低」卡、独立「比赛恢复」卡 —— 老板明确不要，整体删除对应代码分支
