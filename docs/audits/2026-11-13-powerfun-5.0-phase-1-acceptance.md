## 2．阻断项：缺少 context.json 时绕过全部 response 上下文校验

### 2.1 位置与原因

`main.py` 的 `_resolve_llm_report()` 在第 483—503 行附近：

```python
context_file = resp_file.parent / "context.json"
if context_file.exists():
    # 校验 activity_id、user_note_hash、prompt_version、analysis_hash
    ...
problems = _validate_llm_response(content)
```

只有 `context.json` 存在时才校验。文件缺失时不会报错，而是直接检查六小节格式，随后写缓存并生成报告。这意味着缺少上下文或上下文未随 response 一起提供时，`activity_id`、体感、Prompt 版本和 `analysis_hash` 全部被跳过，本批新增的防错配保护可以被无意绕过。

### 2.2 隔离复现

使用临时 `cache`／`runtime` 目录，提供格式合法但没有同目录 `context.json` 的 response，实际结果：

```text
缺失 context.json：被接受，缓存存在=True
```

复现脚本保存在 `.runtime/acceptance/phase1/verify_remaining.py`，没有写正式缓存。

### 2.3 为什么阻断

PRD 第 7.2 节要求 response 上下文校验加入 `analysis_hash`，防止旧分析生成的 response 写到新分析上；当前缺失上下文的分支不能保证这一点。问题改动小，但属于本批核心安全语义，不能以“正常流程通常会生成 context.json”为由豁免。

### 2.4 最小修正要求

1. 第二阶段 `--llm-response` 缺少同目录 `context.json` 时明确报错并非零退出，不写缓存、不生成正式报告。
2. 保持现有正常两阶段流程不变，不改变 note 复用语义，不扩大为本批之外的缓存重构。
3. 新增测试：合法 response 但缺失 `context.json`，断言拒绝且缓存不存在。
4. 复跑针对性测试、全量测试及本次缺失上下文复现；预期缺失上下文结果变为“已拒绝，缓存不存在”。
