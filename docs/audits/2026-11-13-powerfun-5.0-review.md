# PowerFun 5.0 项目审查报告

- 日期：2026-11-13
- 当前产品版本：4.1
- 数据快照：2025-10-24 至 2026-11-12，主表 153 次活动
- 审查范围：代码、文档、历史改动、现有 parquet／分圈／报告／LLM 缓存及确定性测试
- 状态：审查完成；优化原则已与老板确认；生产代码尚未因本报告修改

## 1．结论摘要

PowerFun 当前不需要推倒重写。Garmin 数据获取、主表、分圈、确定性分析和 KimiWork 两阶段点评流程已经能够运行，现有 39 项测试在审查快照中全部通过。

当前主要问题不是“功能不够”，而是部分结果的**课型前提、统计适用范围和结论强度不匹配**：

1. 节奏跑、间歇跑被整场平均心率误分，进而污染轻松跑／有氧耐力跑参照池。
2. Pa:Hr 的公式符号与问题探测方向相反，导致真实漂移被漏报。
3. 节奏课把热身、工作段、恢复段混在一起计算 Pa:Hr；间歇课也不适合计算整场 Pa:Hr。
4. 跨温区趋势被直接解释为能力进步，小样本回归产生了不具备训练意义的月度斜率。
5. LLM 缓存没有覆盖分析结果变化，算法或人工课型改变后可能复用旧点评。
6. 正常最新深析与指定日期深析存在重复实现，后续修补容易发生路径分叉。

因此，5.0 的优先级应是：**先修正事实口径，再限制结论强度，最后处理一般工程问题。** 不引入新的复杂模型，不让模型代替 Python 计算，也不通过扩大数据删除来制造“干净”结果。

## 3．已确认的核心问题

### 3.1 节奏跑和间歇跑误分类

**证据**

当前 153 次活动分类为：101 次轻松跑、20 次有氧耐力跑、25 次 LSD、2 次全马、3 次半马、2 次其他赛事，没有节奏跑或强度训练样本。

但训练记录明确表明：

- 2026-11-06，`659451010`：3 km 热身＋6 km 节奏＋恢复，被分为有氧耐力跑；
- 2026-11-09，`660460268`：连续约 7 km 节奏复试，被分为有氧耐力跑；
- 2026-10-29，`656543045`：5 组 1 km 间歇，被分为轻松跑。

**根因**

自动分类主要使用标题、距离和整场平均心率。混合课的热身、工作段和恢复段会稀释整场强度，平均心率无法可靠还原训练目的。

**影响**

- 高强度课进入轻松跑／有氧跑参照池；
- 历史百分位、短期状态、长期趋势和分圈基线使用了错误同类型样本；
- 报告出现“有氧课高强度超标”，而真正问题是课型标签错误。

**已确认方案**

比赛、LSD、轻松跑、有氧耐力跑等维持既定自动逻辑；节奏跑和间歇跑以人工训练目的覆盖。保留原自动分类和人工来源，不回写历史 parquet。

### 3.2 Pa:Hr 问题探测方向错误

**证据**

现有公式为：

```text
ratio = speed / heart_rate
Pa:Hr = (ratio_second / ratio_first - 1) × 100%
```

因此负值代表后半程速度／心率效率下降。但 `_detect_issues()` 只检查 `pa_hr_pct > +5%`。

在 153 次活动中：

- 41 次 `Pa:Hr ≤ -5%`，不会被当前探测器报告；
- 15 次 `Pa:Hr ≤ -8%`，同样不会按当前方向触发；
- 11 月 6 日节奏课整场为 `-7.56%`，缓存点评却没有对应的确定性漂移问题。

**已确认方案**

公式和符号展示保持不变，问题探测改为 `pa_hr_pct <= -5%`，标题、证据和阈值文案同步使用负号。

### 3.3 Pa:Hr 的段落适用范围不合理

**证据**

- 11 月 6 日：整场 `-7.56%`；人工工作段第 4—9 圈为 `-6.14%`，配速 295→295 秒/km，心率 168→179 bpm。
- 11 月 9 日：整场 `-5.45%`；人工工作段第 5—11 圈为 `-4.12%`，配速 290→291 秒/km，心率 169.1→175.7 bpm。
- 11 月 12 日轻松跑：整场 `+0.92%`，应作为普通跑口径不变的回归对照。

整场计算会把热身、恢复和末端冲刺纳入，结果既包含有氧解耦，也包含课程结构。间歇跑还存在心率滞后，工作段与恢复段混合后的 Pa:Hr 不具备清晰训练含义。

**已确认方案**

- 轻松跑、LSD、比赛、有氧耐力跑：继续保持整场前后半对比，保证历史连续性；
- 节奏跑：只计算人工指定的连续工作段；
- 间歇跑：默认不适用；只有另行指定连续稳态段时，才可计算该段，绝不回退到整场；
- 缺少有效人工段落时输出不适用原因，不填 0。

普通跑的整场 Pa:Hr 应被解释为“本次课程前后半效率变化”，不能过度解释为纯粹的生理有氧解耦。比赛还受起跑、配速策略和末段冲刺影响。

### 3.4 LLM 缓存未覆盖分析输入变化

**证据**

当前缓存只校验 `activity_id`、`user_note_hash` 和 `prompt_version`。人工课型、Pa:Hr 工作段、参照池算法或趋势口径变化时，只要 prompt 版本未升，就可能复用旧点评。

**已确认方案**

对结构化 `analysis_data` 生成稳定哈希，缓存和 response 上下文均校验。`user_note_hash` 继续独立处理；`LLM_PROMPT_VERSION` 只表达 Prompt 协议／结构版本，不再承担所有分析数据失效职责。

### 3.5 跨温趋势被过度解释为能力变化

**证据**

11 月 12 日轻松跑长期趋势使用 57 个跨温样本，输出：

- 心率月降 1.47 bpm；
- 配速每月改善 2.44 秒；
- verdict 为“进步”。

但月度温度中位数从 7—8 月约 30—32°C 降至 10 月约 23°C，同期心率也由约 150 降至 143.5。气温、季节和体能变化混杂，不能把全部改善归因于能力。

温度效率回归也不稳定：仅温度的斜率约为 -0.1969，加日期后约为 -0.4096，再加课型后约为 -0.4497；温度与日期相关系数约 0.567。

**已确认方案**

采用“扩池展示、限制结论”：

- 跨温样本不删除，可描述近期表现轨迹；
- 能力判断优先同温或相近季节，并检查时间覆盖；
- 可比样本不足时明确“无法排除气温和季节影响”；
- 当前不建立个人化“每升高 1°C 慢多少秒”的精确修正模型。

### 3.6 小样本和同比斜率失真

**证据**

去年同期窗口实际只有 3 次活动，却输出：

- 心率 `-32.22 bpm/月`；
- 配速 `+86.18 秒/月`。

这些数值是少量活动日期位置形成的数学斜率，不是可信的能力趋势。

**已确认方案**

- 每组 n≥5 才给谨慎方向，n＝3—4 只描述，n＜3 不比较；
- 长期趋势至少 3 个有效月份，通常每月≥2 次；LSD 每月 1 次但低置信度；
- 增加逐月剔除敏感性检查；
- 同比 3 次可展示中位数，但同比斜率也必须满足多月份覆盖；
- 历史百分位 n≥10 才显示；
- 分圈 P20—P80 按每公里实际有效样本数判断，当前工作区已有 n≥10 的实现，应保留并补验收。

## 4．其他工程与方法问题

以下问题真实存在，但不全部进入 5.0 首批范围，避免同时改变过多口径。

| 问题 | 证据与风险 | 建议处置 |
|---|---|---|
| 正常最新深析重复实现 | `_run_reports()` 的最新分支与 `_generate_deep_report()` 分别加载分圈、分析、历史 Pa:Hr 和渲染 | 第一批合并，保证新逻辑只有一个入口 |
| 分圈统计多份实现 | Prompt 与图表的残圈阈值、IQR 和 P20/P80 平滑口径不完全一致 | 后续单独统一统计内核；本批不改图表数值 |
| FIT 分圈失败后不会自动补拉 | 活动已写主表后，下次只有新增或字段变化才进入 `to_process` | 后续增加缺失分圈修复队列，不与本次报告口径改造混合 |
| 负荷激增参照近 4 次不限课型均值 | 忽略间隔、减量周、连续积累和课型差异 | 后续按 7／28 天负荷与课型背景重新设计 |
| 综合报告强度按活动次数 | 均心落入某区即计一次，不等于实际高强度训练时间 | 后续改为时间占比并识别减量周 |
| 技术变化机械等同进步 | 步频＋2、步幅＋1 cm、GCT－5 ms 即称进步，单次自然波动也可能触发 | 后续改为“变化”，要求连续同向或效率佐证 |
| 标题过滤“间歇跑” | 旧在线清洗路径可能排除标题含间歇的活动，与人工维护间歇课目标冲突 | 后续核查在线路径与 `fetch-new` 路径一致性后单独处理 |
| 比赛 Pa:Hr 解释过强 | 赛道、配速策略和冲刺影响大 | 本批保留数值，但点评只作描述，不单独归因热疲劳或体能下降 |

## 5．统计口径的教练视角评估

### 5.1 合理且应保留的部分

- 历史对比使用中位数，比均值更不容易被单次异常状态拉动；
- Pa:Hr 中速度由总距离／总时长计算、心率按时长加权，优于简单平均圈心率；
- 长期趋势先求每月中位数再回归，比把全部活动等权回归更能降低高频月份的主导作用；
- 普通课型每月至少 2 次、至少 3 个有效月份，是合理的基础护栏；
- 分圈区间带按每公里实际样本量决定是否展示，方向正确。

### 5.2 需要限制的部分

- 中位数只能描述样本中心，不能自动证明能力变化；
- 月度斜率除了样本数，还依赖月份覆盖和对单个月份的敏感性；
- 跑步经济性 `(m/h)/bpm` 可用于同条件比较，但不能脱离气温、课型和配速单独归因；
- 单次步频、步幅、触地时间变化不等于技术进步；
- Pa:Hr 是课程内效率指标，不是独立的过度训练诊断工具；
- 间歇课应优先看各组配速、心率反应和恢复，而不是整场 Pa:Hr。

### 5.3 噪音处理原则

- 技术异常只使对应指标无效，不删除整次活动；
- 课程结构不同属于“不可比”，不等于坏数据；
- 疲劳、睡眠不足和状态差是训练信息，不能作为噪音抹掉；
- IQR 可用于图形分布控制，不应单独成为删除真实训练的依据；
- 不适用返回空值和原因，禁止用 0 代替。

## 6．5.0 优化原则与范围

已确认的四条原则：

1. 只有节奏跑和间歇跑以人工训练目的维护，其他既定自动分类逻辑不变。
2. 普通课型 Pa:Hr 保持整场前后半对比；节奏跑和间歇跑只按人工指定段落处理，间歇默认不适用。
3. 温度不硬排除，采用“描述可扩池、能力结论受限制”。
4. 按指标设置样本门槛，保留真实数据，结论允许“证据不足”。

5.0 正式范围分为：

- 第一批：人工课型、Pa:Hr 双轨、漂移符号、缓存哈希、最新深析入口合并；
- 第二批：短期／长期／同比／百分位样本门槛及跨温结论限制；
- 全部验收后：产品版本由 4.1 升为 5.0，并更新入口文档。

其他工程问题进入后续候选清单，不自动扩大 5.0 范围。
