# PowerFun 跑步数据分析 — 经验教训

## 老板决策（不可推翻）

- **max_hr=188 是有意的保守安排**（2026-08-23 确认）：实测高于 188 的心率很少且多为瞬时峰值，不代表实际心率上限。即使数据中出现 189-194 的记录，也不要建议上调 max_hr。

## 关键技术要点

1. **Garmin.cn 字段映射**：功率 `avgPower`、步频 `averageRunningCadenceInStepsPerMinute`、垂直振幅 `avgVerticalRatio`
2. **心率区间**：API 原生 `hrTimeInZone_1~5` 在 activity 顶层（非 summaryDTO），`averageHR`/`maxHR` 同理
3. **Karvonen HRR**：`HRR = max_hr - resting_hr`；Z1(0.01,0.74) Z2(0.74,0.84) Z3(0.84,0.88) Z4(0.88,0.94) Z5(0.94,1.00)；max_hr=188, resting_hr=60；**唯一方法，绝不用最大心率法**
4. **USER_CONFIG 独立**（v4.0）：`max_hr`/`resting_hr` 提取为独立配置，`HR_ZONE_PERCENTAGES` 写死，零硬编码
5. **报告流程**：综合报告 → 深析报告；`--deep-analyze` 独立不触发综合报告
6. **XSS 防护**：用户输入必须 HTML 转义

## 经验教训

- **官方数据优先**：API 有原生字段时不用本地计算
- **Coder Agent 按 High→Medium→Low 选择性修复**：避免过度工程化
- **数据准确性红线**：清洗只做单位/格式转换，不推导业务指标
- **对比分析基线**：严格按跑步类型隔离（轻松跑只跟轻松跑比），同类型内加温区分桶（三档），降级只放宽温区不放宽类型
- **统计用中位数+P25P75**：替代均值+min-max，抗异常值干扰
- **报告输出**：HTML 为最终形态，自动复制到 iCloud 云盘；PDF 按需通过 `--pdf-only` 从已有 HTML 转换（不重新分析数据）
- **iCloud 复制防死锁**：`shutil.copy2` 覆盖写入会被 iCloud 同步锁阻塞（EDEADLK），必须先 `dst.unlink(missing_ok=True)` 再 copy
- **深度分析距离取整**：prompt 中距离用 `int()` 取整，避免 AI 生成不存在的分段（如 16.2KM 出现"第 17KM"）
- **图表横轴日期**：用 `type='date'` + `tickformat='%m-%d'`，让 Plotly 自动选刻度，不要手动按月分组
- **强度结构卡强度口径**：按 Z2+ 统计强度次数（老板保守 max_hr=188，强度课心率多落 Z2，按 Z3+ 会漏计）

## 2026-10-05 参照物取数逻辑修复（commit 108502f）

**问题**：长期趋势判定出现荒谬「退步」——温区三档分桶（mid=(min+max)/2）× 类型过滤双重切分，凉爽天跑步（mild 桶）的基线只剩 4-6 月 6 次过期样本（7-9 月全 hot 桶）；月度回归 x 轴用月份序号（np.arange）忽略真实时间间隔；6 月唯一样本（6:41 慢速跑）单月单样本直接带歪斜率（配速月降 21.7 秒）。与实际持续进步严重冲突。

**修复**（F1-F5 + G1，已 push）：
- F1 趋势判定基线统一三级选择：同温区(最新样本≤45天)→不限温区(≤45天，标注跨温区)→数据不足（区分样本不足/基线过旧）；月度回归 x 轴改真实月差 (p-p0).n；每月≥2 样本才纳入回归

- F3 分圈基线：优先近90天同温区/跨温区(≥5次)，兜底最近N次；报告+prompt 标注基线构成
- F4 短期三行在跨温区基线时追加「·跨温区基线」
- F5 percentile/expected_pace 基线同步三级选择+新鲜度门槛
- G1 LLM_PROMPT_VERSION=3

**验证**：10-04 场景长期判定由「退步」→「进步（跨温区基线）」（心率月降1.0bpm、配速月升25.0秒、效率月升4.9）；构造用例全过；0924 热天回归不变；0928 LSD 正确显示「基线过旧」。

**教训**：稀疏分桶数据上做趋势回归，必须先守「样本新鲜度」和「单月最小样本量」两条底线；分桶维度（温区×类型）叠加会指数级缩小样本池，取数逻辑要以「时效」为第一优先级。

## 2026-10-12 末公里阴影恢复 + 技术指标长跨度点评（commit 5e0c0ca）

- **末公里阴影缺失根因**：F3 门槛 20→25 叠加残圈过滤，末公里样本被双重压缩（10-11 实例：km16 过滤前 30 → 残圈过滤后 21 < 25）。修复：门槛回退 20（`BAND_MIN_SAMPLES` 常量，配速/心率图共用）。**教训：漏斗爆炸的根因是残圈噪音和锯齿边缘，不是样本门槛——修 bug 要对着根因，别把顺带改动的参数当功劳。**
- **技术指标点评改长跨度口径**（老板指令）：基线 = 同类型 + ≥90天前 + 平均心率±5bpm（相近强度）；只报进步（VR≤-0.2/GCT≤-5ms/步频≥+2/步幅≥+1cm），持平退步静默。业余跑者技术指标固化慢，近期对比全是噪音，长跨度才能看到训练积累。

## 2026-10-12 技术基线改功率口径 + 问题驱动点评（commit 86264f9）

- **技术基线心率口径→功率口径**：技术指标（步频/步幅/VR/GCT）与机械输出耦合而非心率；心率跨体能/季节漂移会把体能进步误报成技术进步（实例：步幅+6.87cm 的"进步"大头是体能红利）。改为 同类型+≥90天前+avg_power±8W → 配速±15s 兜底 → 同类型放宽。预期效果：步幅/步频几乎不再误报，浮现的是 VR/GCT 真实变化。
- **改进建议→问题驱动**：prompt 道德劝说杀不死套路（"允许只给2-3条"在 LLM 听来就是"最好给"）。根因在数据层——新增 `_detect_issues` 5 项确定性探测器（强度偏离课型/Pa:Hr漂移>5%/负荷>近4次均值1.5×/max_hr超上限或同类型P95/VR·GCT劣于基线P80），清单喂给 LLM：空→固定一句「无明显问题」，非空→逐条问题→影响→怎么改。小节改名「🛠️ 问题与修正」。
- **教训**：让 LLM 不说废话的正确姿势是给它一个可以为空的事实清单 + 空时的固定输出，而不是"允许少写"。
- LLM_PROMPT_VERSION=6。

## 2026-10-22 趋势体系重构（commit 63b5242）

- **三层结构**：短期状态（60天基线，45→60）/ 长期趋势（180天全量回归，取消新鲜度门槛）/ 夏季同比（6-9月∪>28°C vs 去年同期，2027-06 数据到位自动激活）。
- **设计教训**：新鲜度门槛是为「当前状态对比」设计的，误套到「长期趋势回归」上是自相矛盾——趋势的本质就是跨月份，掐死原料必然「样本不足」。不同用途的基线要解耦。
- **夏季规则**：SUMMER_MONTHS={6,7,8,9} ∪ 中值>28°C（老板体感：25-27°C 舒适、28°C+ 才是热；25°C 阈值会让 56/60 次训练都成了"夏季"，例外变常态）；夏季内长期判定阈值×2（防热季误报退步）。
- **Coder 两处合理微调**：①同温区选中但月度护栏不过→降级跨温区再试（护栏数值不变，只扩样本池）；②移除长期回归 30 次上限（会把 60 样本截成 30、丢掉 4-6 月，与"180天全量"冲突；月度回归只用每月中位数，样本多不改口径）。
- 验证亮点：10-22 报告长期趋势 7 个月回归出「进步（心率月降1.4bpm，效率月升1.0）」——一年的训练积累第一次被完整量化。
- LLM_PROMPT_VERSION=8。

## 2026-10-25 LSD 豁免温度过滤与月度护栏（commit 0d352fd）

- **老板指令**：LSD 是条件自筛选课型（时间/天气/状态合适才跑，计划 2 周一次、7-9 月因热停跑），能跑即条件合格——LSD 对比豁免温度过滤与月度样本护栏，所有 LSD 同池对比（NO_TEMP_FILTER_CATEGORIES={'lsd'}）。
- 落地：基线选择 LSD 直接不限温区池（scope='no_temp'）；分圈历史跳过同温区档（标注「全部 LSD N 次」）；长期回归月度门槛 LSD ≥1/月（其他类型 ≥2 保留，总 ≥3 月下限不动）。
- 结果：10-25 那场 30km LSD 长期趋势出结果「进步（心率月降1.5bpm，配速月升6.4秒，效率月升1.9）」，percentile P86，同类型中位数快 19 秒。
- **设计启示**：课型对比口径应尊重课型的「采样机制」——日常课型（轻松跑）被动采样需要温度控制；自筛选课型（LSD）主动采样，跑者对条件已做预筛，跨条件对比天然成立。老板画像：半马主项、全马偶发（2025-11、2026-01 各一次）。
- LLM_PROMPT_VERSION=11。
